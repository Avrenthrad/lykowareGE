# ADR 0067 — Authored foot-plant phases and support anchors

Status: Proposed. Owner: Codex. Base: #72 corrected source `e21f797`, verified by all five hosted profiles and 81/81 each local Linux profile. Scope: 02.11c walking position locks; user requested continued project work with integration/manual gates parked.

Add an owned fixed-storage FootPlant state machine behind animation/physics APIs. A plant edge probes the real collision world, stores an ankle point and surface normal in the support body's local frame, and subsequently resolves that anchor through the body's current double-position/rotation. Lift releases it. Missing/steep support, destroyed/stale/cross-world handles or excessive animated-foot distance releases/suppresses it until a new lift/plant cycle. No silent reacquisition while a failed plant remains held. An explicit reset clears the phase, for respawn/teleport/inactive callers. bool-returning failures preserve state and output. Each plant owns no world/body lifetime and performs read-only queries; the world must outlive calls, not necessarily the plant. Successful calls allocate no heap storage. One writer per state; copies support sample bilateral staging.

The character sample optionally consumes authored `left_plant`, `left_lift`, `right_plant`, `right_lift` animation event names. Marker interpretation is sample policy, not hardcoded in the generic graph. Playback retains phases and per-leg cycle epochs, consumes time-zero entry events, and clears phases on state transition/reset. Epoch changes force a fresh anchor even when a lift and replant both occur within one rendered frame. Profiles enable `foot_locking` only alongside foot IK and an authored graph containing all four markers; `foot_max_plant_distance` is finite 0.05..1 metre, default0.35. The profile/inspection/sample paths share settings.

While moving/grounded/visible, plant phases drive foot targets; unplanted legs retain animation. Anchors hold full world position and surface normal, not toe heading or actor/camera transforms. They track support translation/rotation; render interpolation of supports and physical-PC pacing remain separate performance/feel gates. Targets that materially exceed leg reach release rather than stretch or claim a held anchor. Bilateral IK/body state stages and bounded retries restore base animation for released legs, recomputing the visual pelvis correction with the existing both-contact requirement. Single-foot phases do not add body balance. Stationary playback retains the prior stance path. Air/invisible/teleported/invalid-time states reset anchors. All operations remain presentation-only.

Acceptance: analytical static and real Jolt kinematic-translation/rotation support tests, far origin, stale/cross-world handles, slope/distance/phase/refusal and allocation checks; authored event entry/loop/transition/reset through actual graph Playback; moving actor versus held foot and lift/IK reach-release; real profile/sandbox/GPU reference checks. Preserve previous stance/default behavior. No generic gait inference, full foot-yaw lock, moving-support render interpolation, active ragdoll or target-PC acceptance is implied.

Minimal verification tooling: `--play-input FILE` on the actual offscreen Vulkan sample accepts version1 JSON frame intents with bounded repeat counts (6000 expanded frames,64KiB). It drives the existing player input/physics/animation/render loop at a fixed60Hz delta; optional --frames must equal the expanded count. Strict fields/types/bounds/duplicates and mode dependencies are checked before starting the window. `lyko run -- SANDBOX_OPTIONS` forwards owned sample arguments without a shell, preserving the existing scene-command dispatch. This is a sample/headless test driver, not a new editor or gameplay subsystem. It lets tests prove moving PlayerBody marker/anchor integration rather than merely static setup.
