# ADR 0031: Versioned scenes and fixed-tick command replay

Status: Proposed; scoped implementation for the falling-crates fixture.

Scenes and replay streams are strict version-1 JSON, parsed behind Lykoware APIs with vendored nlohmann/json 3.11.3 (MIT). This supplies the first real caller for ADR 0004. Input is bounded to 16 MiB and 10,000 entities/commands. Reject duplicate keys, unknown fields/versions/types, duplicate IDs/sequences, invalid numbers and invalid dimensions. Canonical output uses sorted object keys, compact UTF-8 JSON and a final newline; array order is significant. This is Lykoware canonical JSON v1, not a claim of RFC 8785 conformance.

Scene entities have explicit authored string IDs (ASCII letters, digits, underscore, hyphen; 1–64 characters). An ID is never reused within a scene's lifetime, including after destruction. No runtime handle, address, ECS type ID or world owner token enters files. Versioned component identifiers are explicit strings: `lykoware.box-body@1` and `lykoware.mesh-renderer@1`; the former includes the initial double-precision transform. Only the built-in box/cube fixture is supported; other components require a new documented schema/handler.

Versioned commands are `lykoware.spawn-box@1`, `lykoware.destroy@1`, and `lykoware.set-velocity@1`. Each has an explicit integer tick and unique sequence. A stream is ordered by (tick, sequence); handlers enforce the current simulation tick and increasing sequence within that tick. Commands run before that tick's physics step. A failed command does not advance the tick or ordering cursor; execution stops and reports failure. Successfully applied earlier commands stay applied; there is no whole-stream rollback. No wall clock, render alpha, GPU operation or runtime identity may determine command order or simulation state.

The CLI and future scripting/editor callers use the same Scene::dispatch handler. Presentation camera is separate from authoritative simulation. Renderer interpolation uses snapshots, double-precision position blending and camera-relative subtraction before float conversion; it must not write simulation transforms. A replay test compares every tick's state hash under 30/60/144 Hz and irregular frame partitions, with/without presentation sampling and at far origin. GPU capture checks repeatability and read-only rendering. These are controlled same-build determinism checks, not a promise of arbitrary-version save/network compatibility.

Remaining scope: general component reflection, asset formats/import, saves/migrations, undo, networking and editor UI are later work. This fixture's format establishes boundaries without pretending those systems exist.
