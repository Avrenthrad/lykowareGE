# ADR 0066 — Stationary foot orientation and visual pelvis constraints

Status: Proposed. Owner: Codex. Base: #71 `7197587`. Scope: next runtime work under 02.11c/02.11d; owner explicitly requested continuing the overall project while parking integration/manual gates.

Extend the owned read-only physics ray result with a world-space unit surface normal. Resolve Jolt subshape normals behind the physics interface; no vendor types escape. Preserve body/fraction/point semantics, existing camera callers and state hashes. Reject nonfinite ray directions.

Add immutable prepared joint-axis alignment in the engine. A plan owns parent topology and calibrates a joint-local axis from a rest-model axis. Apply aligns that posed axis to a model-space target with a bounded shortest-arc rotation, changing only that joint's local rotation. Complete spans can overlap; reusable TwoBoneScratch avoids successful-update allocations. Refusal preserves output/diagnostics. Plans may be shared with independent worker scratch; changed skeletons require re-preparation. Unit-scale poses only, same finite/quaternion checks as prepared limb IK.

The sample's stationary foot controller optionally consumes surface normals, rejects downward/too-steep contacts and smooths accepted normals with existing exponential timing/reset policy. Calibrate each ankle axis from rest-model +Y, not an assumed joint-local axis. Convert world normals through actor rotation only (uniform visual scale does not change directions). Apply ankle orientation after bilateral leg positioning. Maximum accepted slope/ankle correction is explicit, defaults 35 degrees when enabled, constrained to 0..60 degrees. Lost/inactive/teleported/invalid-time contacts reset orientation with vertical state.

Optional pelvis compensation lowers the mapped visual pelvis by at most an authored world-space drop (default 0.15 m, 0..0.3). Use the lower accepted foot target when both contacts exist; one missing contact resets compensation. Shift its local translation using the posed parent's orientation and uniform scale, then solve both legs toward their original world targets. Smooth the drop; cap it by calibration (a quarter of the shorter full leg's world length). No physics body/camera movement or segment stretching. This is a bounded stance aid, not balance/locomotion physics. Failure of either leg/orientation preserves all public pose/contact/pelvis state and diagnostics.

Profile additions: `foot_align_normals`, `foot_max_slope_degrees`, `foot_pelvis`, `foot_max_pelvis_drop`. They require `foot_ik`; slope bounds require either stance opt-in and drop bounds require pelvis opt-in. Defaults retain existing vertical-only behavior. Inspection validates settings and reports effective policy. The existing CLI/sample profile path uses the same settings; no editor UI is introduced. Debug counters report oriented/rejected-slope/pelvis frames and actual ECS-palette updates.

Acceptance: analytic joint-axis tests (rotated parents/rest bases, antiparallel, angle bounds, aliasing, lifetime, refusals and allocation reuse); real Jolt slope/heightfield/step probes near/far origin; fitted/yawed coordinates, bilateral and missing-contact cases, 30/60 Hz smoothing, bound/reset/transaction checks, immutable physics hash; actual imported sandbox playback and emitted diagnostics. All five hosted profiles and native full suites required. Walking locks, moving-platform anchoring, active ragdoll and representative rig/crowd/owner hardware gates remain later work.
